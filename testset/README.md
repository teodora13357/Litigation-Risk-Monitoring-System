# testset — 法律文书识别评测集

本目录为「诉讼风险监控系统」法律文书 AI 识别能力的**评测集**：包含 6 类常见法律文书的样例 PDF、人工标注的字段真值（GT）、批量识别结果与评估报告，用于验证和度量识别链路（OCR → 文书分类 → 字段提取）的效果。

## 目录结构

```
testset/
├── 起诉状_仲裁申请书/          # 5 份样例 PDF + GT + 识别结果
├── 判决书_裁定书_调解书/       # 5 份样例 PDF + GT + 识别结果
├── 应诉通知书_参加诉讼通知书/  # 5 份样例 PDF + GT + 识别结果
├── 举证通知书/                 # 5 份样例 PDF + GT + 识别结果
├── 传票_开庭通知书/            # 5 份样例 PDF + GT + 识别结果
├── 上诉状/                     # 1 份样例 PDF + GT + 识别结果
└── Qwen3.6-27B-MTP_eval_report.json  # batch_eval.py 生成的评估报告
```

每个类型子目录内含：

| 文件 | 说明 |
| ---- | ---- |
| `*.pdf` | 该类型真实样例文书（来源已脱敏） |
| `{类型}_gt.json` | 人工标注的字段真值（Ground Truth），评估的基准 |
| `{类型}_results.json` | 批量识别脚本（`batch_test.py`）输出的字段提取结果 |

## 覆盖的文书类型与字段

| 文书类型 | 对应 skill | 提取字段 |
| ---- | ---- | ---- |
| 起诉状 / 仲裁申请书 | `complaint-arbitration-extract` | 原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、标的额、诉讼请求金额、赔偿金 |
| 判决书 / 裁定书 / 调解书 | `judgment-ruling-mediation-extract` | 案号、原告/申请人、被告/被申请人、涉及主体、受理法院/仲裁委、业务类型、标准案由、标的额、赔偿金、诉讼请求金额、裁判结果 |
| 应诉通知书 / 参加诉讼通知书 | `defense-notice-extract` | 案号、原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、立案日期 |
| 举证通知书 | `evidence-notice-extract` | 案号、被告/被申请人、涉及主体、受理法院/仲裁委、标准案由、业务类型、举证期限 |
| 传票 / 开庭通知书 / 改期开庭通知书 | `summons-hearing-extract` | 案号、被告/被申请人、涉及主体、受理法院/仲裁委、应到时间、标准案由、业务类型、应到地点 |
| 上诉状 | `appeal-extract` | 案号、原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、标的额、诉讼请求金额、上诉请求 |

字段值约定：

- **业务类型**：枚举值，如 `民事诉讼‑侵权纠纷`、`劳动仲裁`；信息不足时填 `无法根据已有信息推断`
- **标准案由**：仅在「映射表关键词命中」或「案由名称完整直接出现在文书原文」时输出，否则 `null`
- **原告/申请人、被告/被申请人**：数组
- **涉及主体**：数组，**只能**从 13 家备选主体名单中提取（全称或简称还原为名单全称），名单之外不提取，无可识别主体填 `null`
- **举证期限**：具体日期输出 `YYYY-MM-DD`；相对期限**保留原文形式**（中文数字保留中文，如 `五天内`、`十五日内`；阿拉伯数字保留阿拉伯，如 `7日内`）
- **标的额 / 诉讼请求金额 / 赔偿金**：数值类型（元），保留原文全精度
- **结果文件中每个字段**：`{"value", "编辑距离", "置信度"}`；`置信度` 为该字段 20 次投票中众数占比（0-100）
- **提取说明**：结果文件中的说明字段，逐字段记录提取依据；GT 中不参与评分

## 评估工作流

评测分两步：先批量识别，再与 GT 对比评分。

### 1. 批量识别（生成 results）

```bash
python extractor_test/batch_test.py testset
```

流程：

1. **OCR 解析**：每个类型子目录的 PDF 并行提交到解析服务（默认 `http://192.168.10.250:8000`，`parse_method=auto`，`backend=hybrid-engine`），轮询等待解析完成，产出 Markdown 文本
2. **LLM 提取**：每份文书先做类型判定，再加载对应 skill（`prompts/skills/`）逐字段提取；每份文书投票 20 次（`NUM_VOTES=20`，并发 2 个 voter）取众数；每个 voter 先按 `ref.json` 字段清单规整，再做**全字段溯源**（除 `SKIP_PROVENANCE_FIELDS`），未溯源通过的字段带提示重生成（≤ `MAX_REGEN` 次）

> 脚本内的服务地址、模型（`Qwen3.6-27B`）、投票次数等参数见 `extractor_test/batch_test.py` 顶部常量，可按环境调整。

### 2. 评估打分（生成 eval_report）

```bash
python extractor_test/batch_eval.py testset
```

对每个类型子目录读取 `{类型}_results.json` 与 `{类型}_gt.json` 逐字段对比，输出到 `Qwen3.6-27B-MTP_eval_report.json` 并打印总体匹配率与平均置信度。

**对比规则**（见 `extractor_test/batch_eval.py`）：

- 文档名、字段值先做归一化：去空白、去 `.pdf` 后缀、全角转半角、统一括号与连字符、中文数字转阿拉伯数字
- 空值（`null` / `none` / `无法根据已有信息推断` / 空串）视为等价
- 数组值排序后比较；标量按归一化字符串比较
- GT 手写错误（缺逗号、全角逗号、尾随逗号、数值带单位）由 `load_json_lenient` 容错修复
- 结果文件要求：每个子目录**恰有 1 个** `*_results.json` 与 `*_gt.json`；GT 每项必须为含 `提取说明` 键的文档对象

## 评估报告结构

`Qwen3.6-27B-MTP_eval_report.json` 顶层含 `root`、按子目录排列的 `folders`、以及 `overall_*` 汇总：

- `folders[i].doc_stats`：逐文档字段级对比（`匹配` / `gt` / `结果` / `置信度`）、单文档匹配率与 `avg_置信度`
- `folders[i].field_rates`：按字段聚合的匹配率（`matched` / `total` / `match_rate`）与 `avg_置信度`
- `folders[i].total_match_rate`、`folders[i].avg_置信度`：该文书类型的整体匹配率与平均置信度
- `overall_match_rate`：全部类型、全部字段的总体匹配率
- `overall_avg_置信度`：全部字段的平均置信度

| 文书类型 | 份数 | 匹配率 | 字段合计 | 平均置信度 |
| ---- | ---- | ---- | ---- | ---- |
| 上诉状 | 1 | 70.00% | 10 | 83.5 |
| 举证通知书 | 5 | 85.71% | 35 | 93.1 |
| 传票_开庭通知书 | 5 | 62.50% | 40 | 99.0 |
| 判决书_裁定书_调解书 | 5 | 83.64% | 55 | 98.3 |
| 应诉通知书_参加诉讼通知书 | 5 | 90.00% | 40 | 96.5 |
| 起诉状_仲裁申请书 | 5 | 85.00% | 40 | 98.4 |

已知短板：

- **长文本字段**（`裁判结果`）按全文精确归一化比对，命中率偏低（60%），建议改为语义/关键信息比对
- **传票类**：`应到地点`、`受理法院/仲裁委`（如"仲裁院"vs"仲裁委"）、`标准案由`（GT 为 null 时模型仍输出）等存在差异
- **金额类字段**：个别文书存在数值错误（如 `11000` 提取为 `1100`）
- **兼容字/格式差异**：`⺠`/`民`、`⼴`/`广`、全角/半角等归一化后仍有个别失配

> 完整逐字段明细见 `Qwen3.6-27B-MTP_eval_report.json`。

## 维护说明

- 新增样例：在对应类型子目录放入 PDF，编写同名 GT 条目（含 `提取说明` 键），并保持每目录 1 个 `*_results.json` / `*_gt.json`
- GT 的 `提取说明` 仅用于人工核验提取依据，不参与匹配率统计
- 本目录已被 `.gitignore` 忽略（样例文书含真实涉诉信息），不随仓库提交

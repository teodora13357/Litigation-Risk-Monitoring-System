# 举证通知书字段提取

## 适用范围

- **仅适用于**"举证通知书"类文书
- **输入**：文书全文内容（文本）
- **输出**：固定 JSON 格式的字段提取结果
- 若文书不属于举证通知书，**立即终止**，输出 `{"错误": "该文书不在可解析范围内"}`

## 硬性约束（违反即终止）

1. **仅提取**下述 7 个字段，不提取任何其他信息
2. **禁止修改**、移动、删除任何文件
3. **禁止输出**法律建议、分析意见或风险提示
4. **禁止编造**字段值--所有字段值必须来源于文书原文
5. **禁止推断**未在文书中明确出现的实体名称
6. 无法提取的字段输出 `null`，并在 `提取说明` 中注明原因
7. 7 个字段**必须全部输出**，不可省略任何字段

## 字段提取规则

- 名单之外的实体（自然人、其他法人）-> **一律不提取**
- 若触发词命中的实体均不在名单内 -> `涉及主体` 输出 `null`

### 1. 案号（正则匹配）

**提取方式**：正则匹配

**正则表达式**（严格匹配，大小写敏感）：

```
\((\d{4})\)([\u4e00-\u9fa5]+\d+\w*)(\w+)(\d+)号
```

**规则**：
- 在文书全文中执行正则搜索
- 若命中多个案号，取**最先出现**的一个
- 输出案号**完整原文**（如 `(2024)粤0106民初1234号`），不做截断或改写
- 若未命中任何案号，输出 `null`

### 2. 被告/被申请人（NER 实体识别）

**提取方式**：基于上下文触发词的实体识别

**触发词**（命中任一即启动识别）：`被告`、`被申请人`、`被诉人`、`被申诉人`、`被上诉人`、`被传唤人`

**实体识别规则**：
1. 定位触发词在文书中的位置
2. 从触发词之后开始扫描，跳过标签分隔符（`：`、`:`、空格）
3. 提取紧随其后的实体名称，实体类型判定如下：
   - **自然人**：2–4 个连续汉字，支持少数民族姓名（含 `·` 分隔符，如 `买买提·艾力`），遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
   - **法人/组织**：以 `有限公司`、`股份有限公司`、`集团`、`公司`、`厂`、`社`、`院`、`中心`、`事务所`、`合作社`、`个体工商户` 等组织后缀结尾的连续文本，遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
4. 一行内可能出现多个实体（以 `、`、`，` 分隔），全部提取
5. 跨行出现的多个被告（如"被告：张三\n被告：李四"），全部提取

**角色排除**：
- 排除审判人员（`审判长`、`审判员`、`法官`、`陪审员`）、书记员、代理人（`律师`、`法律工作者`）等角色人名，通过上下文角色词区分，仅提取当事人名称

**简称与全称**：
- 识别简称与全称的对应关系（如"番茄站公司"为"番茄站智能科技有限公司"的简称），同一实体保留**全称**

**冲突处理**：
- 若触发词后紧跟的是地址、电话等非名称信息（以 `住`、`住址`、`地址`、`电话`、`身份证` 开头），跳过该段，继续向后查找名称实体
- 若触发词后无任何可识别实体，该位置标记为未命中，继续搜索下一个触发词出现处

**文书开头兜底识别**（触发词未命中时）：
1. 举证通知书常以"*公司（单位/你单位）："等抬头开头，抬头中的公司/组织通常即本案**被告/被申请人**
2. 若全文**未命中**上述触发词（`被告`、`被申请人` 等）：
   - 检查**文书开头**（标题之后、正文之前，通常为前 1–3 行）是否有以组织后缀结尾的实体（`有限公司`、`股份有限公司`、`公司`、`中心`、`事务所`、`合作社`、`厂` 等）
   - 将开头出现的公司/组织名称提取为被告/被申请人，简称还原为全称
   - 开头出现多个实体时，结合上下文排除原告方（如"原告：XXX"后出现的原告），其余判为被告/被申请人
3. 该来源在 `提取说明` 中注明为 `文书开头识别`

**输出**：数组，如 `["番茄站智能科技有限公司"]` 或 `["张三", "李四"]`；若无任何命中，输出 `null`

### 3. 涉及主体（NER 实体识别）

**提取方式**：聚合所有具名当事人（**仅限备选主体名单内**）

**识别范围**：从以下角色上下文中提取全部实体名称，并对照第 0 节备选名单过滤：
- 原告/申请人：触发词 `原告`、`申请人`
- 被告/被申请人（复用字段 2 结果）
- 第三人：触发词 `第三人`
- 上诉人/被上诉人：触发词 `上诉人`、`被上诉人`
- 其他诉讼参与人：触发词 `证人`、`鉴定人`

**候选名单过滤**（硬性）：
- 仅保留与第 0 节备选名单**匹配**的实体（全称匹配或简称还原为名单全称）
- 名单外的自然人、法人一律剔除
- 简称还原：如 `番茄站公司` -> `番茄站智能科技有限公司`

**去重规则**：
- 同一实体名称（完全一致）仅保留一次

**输出**：数组，如 `["番茄站智能科技有限公司"]`；仅含名单内主体，若无任何命中，输出 `null`

**备注**：一期不接企查查，仅基于文书原文识别；四期增加工商库交叉验证。

### 4. 受理法院/仲裁委（NER 实体识别）

**提取方式**：模式匹配

**识别规则**：

按以下优先级依次尝试提取，取首个命中结果：

1. **从案号提取**：
   - 若字段 1 已提取到案号，从案号中提取法院/仲裁委代码部分（如 `(2024)粤0106民初1234号` 中的 `粤0106`），结合文书上下文还原为全称
2. **从文书全文正则匹配**（优先）：
   - 法院模式：`[\u4e00-\u9fa5]+人民法院`
   - 仲裁委模式：`[\u4e00-\u9fa5]+仲裁委员会`、`[\u4e00-\u9fa5]+劳动人事争议仲裁委员会`
3. **法院层级识别**：通过名称关键词判定层级：
   - `最高人民法院` -> 最高
   - `高级人民法院` -> 高级
   - `中级人民法院` -> 中级
   - 其余 `人民法院` -> 基层
4. 取**最先出现**的匹配结果

**输出**：单值字符串，输出**全称**，如 `"广州市天河区人民法院"`；若无任何命中，输出 `null`

### 5. 标准案由（案由映射表匹配）

**提取方式**：关键词分类，从案由映射表中匹配

#### 案由映射表

| 标准案由 | 识别关键词（命中任一即判定） |
|---------|---------------------------|
| 确认劳动关系纠纷 | 确认劳动关系、事实劳动关系 |
| 追索劳动报酬纠纷 | 劳动报酬、拖欠工资、欠薪、加班费、提成工资 |
| 工伤保险待遇纠纷 | 工伤、工伤保险、伤残补助、停工留薪 |
| 经济补偿金纠纷 | 经济补偿、解除劳动合同、违法解除、辞退补偿 |
| 新就业形态用工合同纠纷 | 新就业形态、外卖骑手、网约车、平台用工 |
| 劳动争议 | 劳动争议 |
| 劳务合同纠纷 | 劳务合同、劳务费、劳务报酬 |
| 承揽合同纠纷 | 承揽合同、加工定作、定作合同 |
| 服务合同纠纷 | 服务合同、服务费、中介服务费 |
| 肖像权纠纷 | 肖像、肖像权 |
| 提供劳务者受害责任纠纷 | 提供劳务（须同时出现 受害/受伤/人身损害） |
| 提供劳务者致害责任纠纷 | 提供劳务（须同时出现 致害/致人损害/造成他人） |
| 机动车交通事故责任纠纷 | 机动车交通事故、车祸 |
| 非机动车交通事故责任纠纷 | 非机动车交通事故、电动车交通事故 |
| 网络侵权责任纠纷 | 网络侵权、网络名誉权、网络传播侵权 |

#### 匹配规则

1. 对文书全文逐条执行关键词子串匹配，统计每个案由的命中关键词数量
2. **单案由命中**：仅一个案由命中关键词 -> 直接判定为该案由
3. **多案由命中**：取命中关键词数量最多者
4. **平局处理**：若多个案由命中数量相同，取映射表中**靠前**者（按上表顺序）
5. **特殊规则**：
   - "提供劳务者受害责任纠纷"与"提供劳务者致害责任纠纷"共享"提供劳务"关键词，须通过第二关键词（`受害`/`受伤`/`人身损害` vs `致害`/`致人损害`/`造成他人`）区分
   - 仅出现"提供劳务"而未出现任何第二关键词时，**两个案由均不命中**

#### 未命中处理

- 若所有案由关键词均未命中 -> `标准案由` 输出 `null`，注明 `未匹配到已知案由`
- **直接提取**：`标准案由` 名称**完整直接出现**在文书原文中（如文书写明"机动车交通事故责任纠纷"）-> 直接输出该案由，无需额外命中关键词
- **硬性约束（必须遵守）**：
  - 案由判定**只能**使用上方映射表中的关键词，禁止使用映射表之外的关键词（如"交通事故"、"借款合同"、"劳务纠纷"等）
  - 若映射关键词未命中、且案由名称未完整直接出现在原文中 -> `标准案由` **一律输出 `null`**，禁止根据文书内容自行推断、概括或输出任何案由

**输出**：单值字符串，如 `"机动车交通事故责任纠纷"`；若无命中，输出 `null`

### 6. 业务类型（映射表推理）

**提取方式**：根据字段 5 已提取的"标准案由"，通过业务类型映射表推理

#### 业务类型映射表

| 业务类型 | 标准案由 |
|---------|---------|
| 劳动仲裁 | 确认劳动关系纠纷、追索劳动报酬纠纷、工伤保险待遇纠纷、经济补偿金纠纷、新就业形态用工合同纠纷、劳动争议 |
| 民事诉讼-合同纠纷 | 劳务合同纠纷、承揽合同纠纷、服务合同纠纷 |
| 民事诉讼-侵权纠纷 | 肖像权纠纷、提供劳务者受害责任纠纷、提供劳务者致害责任纠纷、机动车交通事故责任纠纷、非机动车交通事故责任纠纷、网络侵权责任纠纷 |

#### 推理规则

1. 取字段 5 已提取的"标准案由"值
2. 在映射表中精确匹配：
   - **命中** -> 输出对应的业务类型
   - **未命中**（标准案由为 `null`，或标准案由不在映射表中）-> 输出 `无法根据已有信息推断`

**输出**：单值字符串，如 `"劳动仲裁"`、`"民事诉讼-合同纠纷"`、`"民事诉讼-侵权纠纷"`；无法判断时输出 `无法根据已有信息推断`

### 7. 举证期限（模式匹配 + 日期/期限提取）

**提取方式**：关键词触发 + 日期/期限正则匹配

**触发词**（命中任一即启动识别）：`举证期限`、`举证期间`、`举证时限`、`提交证据`、`于...日内举证`、`次日起...日内`、`收到本通知书次日起...天内`

**识别规则**：

1. 定位触发词后，在其后 **50 字符**范围内搜索以下格式：
   - **具体日期**：`(\d{4})年(\d{1,2})月(\d{1,2})日` 或 `(\d{4})-(\d{1,2})-(\d{1,2})`，常见于 `举证期限至…届满` 结构
   - **相对期限**：阿拉伯数字或中文数字 + 时限单位，如 `(\d+)日内`、`(\d+)天内`、`[一二三四五六七八九十]+日内`、`[一二三四五六七八九十]+天内`
2. **期限标准化**：
   - 具体日期 -> 输出 `YYYY-MM-DD` 格式（月、日补零，如 `2026 年5 月17 日` -> `2026-05-17`）
   - 相对期限 -> 保留原文（数字形式），输出 `<N>日内` 格式（如 `7日内`、`十五日内`、`5天内`）
3. 提取**最先出现**的命中结果

**无法判定的情况**：

- 文书中无任何举证期限相关上下文 -> 输出 `null`，注明 `文书未包含举证期限信息`
- 有触发词但未匹配到日期/期限 -> 输出 `null`，注明 `举证期限信息无法解析`

**输出**：字符串，如 `"2026-05-17"` 或 `"7日内"`；若无，输出 `null`

# 法律文书字段提取

## 适用范围

- **仅适用于**"文件解析判断"skill 判定为"需完整解析"的 9 类文书
- **输入**：文书全文内容（文本）
- **输出**：固定 JSON 格式的字段提取结果
- 若文书不属于 9 类需解析文书，**立即终止**，输出 `{"错误": "该文书不在可解析范围内"}`

## 硬性约束（违反即终止）

1. **仅提取**下述 15 个字段，不提取任何其他信息
2. **禁止修改**、移动、删除任何文件
3. **禁止输出**法律建议、分析意见或风险提示
4. **禁止编造**字段值--所有字段值必须来源于文书原文
5. **禁止推断**未在文书中明确出现的实体名称
6. 无法提取的字段输出 `null`，并在 `提取说明` 中注明原因
7. 15 个字段**必须全部输出**，不可省略任何字段

## 字段提取规则

### 1. 案号（正则匹配）

**提取方式**：正则匹配

**正则表达式**（严格匹配，大小写敏感）：

```
\((\d{4})\)([\u4e00-\u9fa5]+\d+\w*)(\w+)(\d+)号
```

**规则**：
- 在文书全文中执行正则搜索
- 若命中多个案号，取**最先出现**的一个
- 输出案号**完整原文**（如 `(2024)粤0106民初1234号`），不做截断或改写
- 若未命中任何案号，输出 `null`

### 2. 原告/申请人（NER 实体识别）

**提取方式**：基于上下文触发词的实体识别

**触发词**（命中任一即启动识别）：`原告`、`申请人`、`起诉人`、`申诉人`、`再审申请人`

**实体识别规则**：
1. 定位触发词在文书中的位置
2. 从触发词之后开始扫描，跳过标签分隔符（`：`、`:`、空格）
3. 提取紧随其后的实体名称，实体类型判定如下：
   - **自然人**：2–4 个连续汉字，支持少数民族姓名（含 `·` 分隔符，如 `买买提·艾力`），遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
   - **法人/组织**：以 `有限公司`、`股份有限公司`、`集团`、`公司`、`厂`、`社`、`院`、`中心`、`事务所`、`合作社`、`个体工商户` 等组织后缀结尾的连续文本，遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
4. 一行内可能出现多个实体（以 `、`、`，` 分隔），全部提取
5. 跨行出现的多个原告（如"原告：张三\n原告：李四"），全部提取

**角色排除**：
- 排除审判人员（`审判长`、`审判员`、`法官`、`陪审员`）、书记员、代理人（`律师`、`法律工作者`）等角色人名，通过上下文角色词区分，仅提取当事人名称

**简称与全称**：
- 识别简称与全称的对应关系（如"番茄站公司"为"番茄站智能科技有限公司"的简称），同一实体保留**全称**

**冲突处理**：
- 若触发词后紧跟的是地址、电话等非名称信息（以 `住`、`住址`、`地址`、`电话`、`身份证` 开头），跳过该段，继续向后查找名称实体
- 若触发词后无任何可识别实体，该位置标记为未命中，继续搜索下一个触发词出现处

**输出**：数组，如 `["张明华"]` 或 `["张明华", "李四"]`；若无任何命中，输出 `null`

### 3. 被告/被申请人（NER 实体识别）

**提取方式**：同字段 2

**触发词**（命中任一即启动识别）：`被告`、`被申请人`、`被诉人`、`被申诉人`、`被上诉人`、`被传唤人`

**实体识别规则**：同字段 2 的规则 1–5

**角色排除**：同字段 2

**简称与全称**：同字段 2

**冲突处理**：同字段 2

**输出**：数组；若无任何命中，输出 `null`

### 4. 涉及主体（NER 实体识别）

**提取方式**：聚合所有具名当事人，人名/法人名

**识别范围**：从以下角色上下文中提取全部实体名称：
- 原告/申请人（复用字段 2 结果）
- 被告/被申请人（复用字段 3 结果）
- 第三人：触发词 `第三人`
- 上诉人/被上诉人：触发词 `上诉人`、`被上诉人`
- 其他诉讼参与人：触发词 `证人`、`鉴定人`

**去重规则**：
- 同一实体名称（完全一致）仅保留一次
- 若自然人与法人名称相同（极少情况），保留两处并在 `提取说明` 中注明

**输出**：数组，如 `["张明华", "番茄站智能科技有限公司"]`；若无任何命中，输出 `null`

**备注**：一期不接企查查，仅基于文书原文识别；四期增加工商库交叉验证。

### 5. 涉及客户（上下文推理）

**提取方式**：从委托代理关系、"委托人"上下文推理出我方客户

**识别规则**：
1. 在文书中搜索委托代理相关上下文，触发词：`委托人`、`委托`、`受托人`、`委托代理人`、`代理人`、`特别授权`、`一般授权`
2. 定位触发词后，识别被代理方（即委托人/客户）：
   - 格式 `委托人：XXX` 或 `委托人XXX` -> XXX 为涉及客户
   - 格式 `XXX委托YYY律师事务所ZZZ律师` -> XXX 为涉及客户
   - 格式 `XXX委托YYY（律师/代理人）` -> XXX 为涉及客户
3. 被代理方应与字段 2/3/4 中的某一实体**匹配**（完全一致或为其中子串）
4. 若文书中有多个委托关系，取**最先出现**的委托人所对应的被代理方

**无法判定的情况**：
- 文书中无任何委托代理相关上下文 -> 输出 `null`，注明 `文书未包含委托代理信息`
- 有委托上下文但无法确定被代理方 -> 输出 `null`，注明 `委托关系存在但被代理方无法确定`

**输出**：单值字符串，如 `"深圳XX科技公司"`；若无，输出 `null`

### 6. 标准案由 + 7. 业务类型（联动提取）

**提取方式**：关键词分类 + 映射表反查

**提取顺序**：先识别"标准案由"，再从映射表反查"业务类型"

#### 案由映射表

| 标准案由 | 业务类型 | 识别关键词（命中任一即判定） |
|---------|---------|---------------------------|
| 确认劳动关系纠纷 | 劳动仲裁 | 确认劳动关系、事实劳动关系 |
| 追索劳动报酬纠纷 | 劳动仲裁 | 劳动报酬、拖欠工资、欠薪、加班费、提成工资 |
| 工伤保险待遇纠纷 | 劳动仲裁 | 工伤、工伤保险、伤残补助、停工留薪 |
| 经济补偿金纠纷 | 劳动仲裁 | 经济补偿、解除劳动合同、违法解除、辞退补偿 |
| 新就业形态用工合同纠纷 | 劳动仲裁 | 新就业形态、外卖骑手、网约车、平台用工 |
| 劳动争议 | 劳动仲裁 | 劳动争议 |
| 劳务合同纠纷 | 民事诉讼-合同纠纷 | 劳务合同、劳务费、劳务报酬 |
| 承揽合同纠纷 | 民事诉讼-合同纠纷 | 承揽合同、加工定作、定作合同 |
| 服务合同纠纷 | 民事诉讼-合同纠纷 | 服务合同、服务费、中介服务费 |
| 肖像权纠纷 | 民事诉讼-侵权纠纷 | 肖像、肖像权 |
| 提供劳务者受害责任纠纷 | 民事诉讼-侵权纠纷 | 提供劳务（须同时出现 受害/受伤/人身损害） |
| 提供劳务者致害责任纠纷 | 民事诉讼-侵权纠纷 | 提供劳务（须同时出现 致害/致人损害/造成他人） |
| 机动车交通事故责任纠纷 | 民事诉讼-侵权纠纷 | 机动车交通事故、车祸 |
| 非机动车交通事故责任纠纷 | 民事诉讼-侵权纠纷 | 非机动车交通事故、电动车交通事故 |
| 网络侵权责任纠纷 | 民事诉讼-侵权纠纷 | 网络侵权、网络名誉权、网络传播侵权 |

#### 匹配规则

1. 对文书全文逐条执行关键词子串匹配，统计每个案由的命中关键词数量
2. **单案由命中**：仅一个案由命中关键词 -> 直接判定为该案由
3. **多案由命中**：取命中关键词数量最多者
4. **平局处理**：若多个案由命中数量相同，取映射表中**靠前**者（按上表顺序）
5. **特殊规则**：
   - "提供劳务者受害责任纠纷"与"提供劳务者致害责任纠纷"共享"提供劳务"关键词，须通过第二关键词（`受害`/`受伤`/`人身损害` vs `致害`/`致人损害`/`造成他人`）区分
   - 仅出现"提供劳务"而未出现任何第二关键词时，**两个案由均不命中**
6. 确定标准案由后，从映射表反查对应的业务类型

#### 未命中处理

- 若所有案由关键词均未命中：
  - `标准案由` 输出 `null`，注明 `未匹配到已知案由`
  - `业务类型` 输出 `null`

**输出**：
- `业务类型`：单值字符串，如 `"劳动仲裁"`
- `标准案由`：单值字符串，如 `"追索劳动报酬纠纷"`

### 8. 受理法院/仲裁委（NER 实体识别）

**提取方式**：模式匹配

**识别规则**：

按以下优先级依次尝试提取，取首个命中结果：

1. **从案号提取**（优先）：
   - 若字段 1 已提取到案号，从案号中提取法院/仲裁委代码部分（如 `(2024)粤0106民初1234号` 中的 `粤0106`），结合文书上下文还原为全称
2. **从文书全文正则匹配**：
   - 法院模式：`[\u4e00-\u9fa5]+人民法院`
   - 仲裁委模式：`[\u4e00-\u9fa5]+仲裁委员会`、`[\u4e00-\u9fa5]+劳动人事争议仲裁委员会`
3. **法院层级识别**：通过名称关键词判定层级：
   - `最高人民法院` -> 最高
   - `高级人民法院` -> 高级
   - `中级人民法院` -> 中级
   - 其余 `人民法院` -> 基层
4. 取**最先出现**的匹配结果

**输出**：单值字符串，输出**全称**，如 `"广州市天河区人民法院"`；若无任何命中，输出 `null`

### 9. 代理人信息（NER 实体识别 + 模式匹配）

**提取方式**：基于上下文触发词的实体识别

**触发词**（命中任一即启动识别）：`委托代理人`、`委托代理`、`代理人`、`辩护人`

**识别规则**：
1. 定位触发词在文书中的位置
2. 跳过标签分隔符（`：`、`:`、空格）后，提取代理人姓名（2–4 个连续汉字，遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止）
3. 继续向后扫描 50 字符范围内，提取以下附加信息（若存在）：
   - **律师事务所**：匹配模式 `[\u4e00-\u9fa5]+律师事务所`、`[\u4e00-\u9fa5]+律师集团`
   - **代理人身份**：匹配关键词 `律师`、`法律工作者`、`实习律师`、`近亲属`、`公民代理人`、`基层法律服务工作者`
4. 跨行出现的多个代理人（如多个"委托代理人"段落），全部提取

**格式模式示例**：
- `委托代理人张三，广东XX律师事务所律师` -> {"姓名": "张三", "律所": "广东XX律师事务所", "身份": "律师"}
- `委托代理人：李四` -> {"姓名": "李四", "律所": null, "身份": null}
- `代理人王五（北京市YY律师事务所）` -> {"姓名": "王五", "律所": "北京市YY律师事务所", "身份": null}

**输出**：数组，每个元素为对象 `{"姓名": "...", "律所": "..." 或 null, "身份": "..." 或 null}`；若无任何命中，输出 `null`

### 10. 标的额（模式匹配 + 金额提取）

**提取方式**：关键词触发 + 金额正则匹配

**触发词**（命中任一即启动识别）：`标的额`、`标的金额`、`涉案金额`、`争议金额`

**金额正则**：`([\d,]+\.?\d*)\s*(万元|元)`

**识别规则**：
1. 定位触发词后，在其后 **50 字符**范围内搜索金额正则匹配
2. 提取首个命中的金额数值
3. **金额标准化**：统一转换为以"元"为单位的数值
   - `万元` 结尾 -> 数值 × 10000
   - `元` 结尾 -> 原数值
   - 去除千分位逗号（如 `50,000` -> `50000`）
4. 原始金额文本记录在 `提取说明` 中

**输出**：数值（单位：元），如 `50000`；若无任何命中，输出 `null`

### 11. 赔偿金（模式匹配 + 金额提取）

**提取方式**：同字段 10

**触发词**（命中任一即启动识别）：`赔偿金`、`赔偿款`、`损害赔偿`、`赔偿金额`

**识别规则**：同字段 10 的规则 1–4

**输出**：数值（单位：元）；若无任何命中，输出 `null`

### 12. 诉讼请求金额（模式匹配 + 金额提取）

**提取方式**：同字段 10

**触发词**（命中任一即启动识别）：`诉讼请求`、`请求判令`、`请求支付`、`请求赔偿`、`诉请`

**识别规则**：
1. 定位触发词后，在其后 **100 字符**范围内搜索金额正则匹配
2. 若命中多个金额，取**总额**（求和后标准化）
3. 若仅命中一个金额，直接标准化输出
4. 金额标准化规则同字段 10

**输出**：数值（单位：元）；若无任何命中，输出 `null`

### 13. 立案日期（模式匹配 + 日期提取）

**提取方式**：关键词触发 + 日期正则匹配

**触发词**（命中任一即启动识别）：`立案`、`受理`、`立案日期`、`受理日期`

**日期正则**：`(\d{4})年(\d{1,2})月(\d{1,2})日` 或 `(\d{4})-(\d{1,2})-(\d{1,2})`

**识别规则**：
1. 定位触发词后，在其后 **30 字符**范围内搜索日期正则匹配
2. 提取首个命中的日期
3. **日期标准化**：统一输出为 `YYYY-MM-DD` 格式（月、日补零，如 `2024年3月5日` -> `2024-03-05`）

**输出**：字符串，如 `"2024-03-15"`；若无任何命中，输出 `null`

### 14. 开庭日期（模式匹配 + 日期提取）

**提取方式**：同字段 13

**触发词**（命中任一即启动识别）：`开庭`、`开庭时间`、`开庭日期`、`定于`、`本院定于`

**识别规则**：同字段 13 的规则 1–3

**输出**：字符串，如 `"2024-05-20"`；若无任何命中，输出 `null`

### 15. 裁判日期（模式匹配 + 日期提取）

**提取方式**：同字段 13

**触发词**（命中任一即启动识别）：`判决如下`、`裁定如下`、`本判决`、`本裁定`、`宣判`

**识别规则**：
1. **优先**在文书末尾落款区域（最后 **200 字符**）搜索日期正则匹配
2. 若落款区域未命中，在触发词后 **50 字符**范围内搜索
3. 提取首个命中的日期
4. 日期标准化规则同字段 13

**输出**：字符串，如 `"2024-06-10"`；若无任何命中，输出 `null`

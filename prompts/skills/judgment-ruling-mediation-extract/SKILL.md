# 判决书/裁定书/调解书/仲裁裁决书字段提取

## 适用范围

- **仅适用于**"判决书/裁定书/调解书/仲裁裁决书"类文书
- **输入**：文书全文内容（文本）
- **输出**：固定 JSON 格式的字段提取结果
- 若文书不属于判决书/裁定书/调解书/仲裁裁决书，**立即终止**，输出 `{"错误": "该文书不在可解析范围内"}`

## 硬性约束（违反即终止）

1. **仅提取**下述 11 个字段，不提取任何其他信息
2. **禁止修改**、移动、删除任何文件
3. **禁止输出**法律建议、分析意见或风险提示
4. **禁止编造**字段值--所有字段值必须来源于文书原文
5. **禁止推断**未在文书中明确出现的实体名称
6. 无法提取的字段输出 `null`，并在 `提取说明` 中注明原因
7. 11 个字段**必须全部输出**，不可省略任何字段
8. **裁判结果为必提字段**：只要文书包含裁判/裁定/调解主文，就必须提取；仅在文书完全无裁判结果时输出 `null`
9. **禁止四舍五入 / 截取小数位**：金额字段（`标的额`/`赔偿金`/`诉讼请求金额`）必须保留原文全部小数位——不得四舍五入（如 `832552.665` 不得输出 `832552.67`），不得截断小数（不得输出 `832552`）；求和结果同样保留精确小数位，不得舍入
10. **金额一律输出为阿拉伯数字**：金额字段统一输出为**十进制数值**（如 `2000`、`832552.665`），不得输出汉字/大写金额（不得输出 `二千`、`贰仟元`）。原文金额为汉字时先归一化为数字再输出（如 原文`二千元` -> 输出 `2000`）

### 1. 案号（正则匹配）

**提取方式**：正则匹配

**正则表达式**（严格匹配，大小写敏感）：

```
\((\d{4})\)([\u4e00-\u9fa5]+\d+\w*)(\w+)(\d+)号
```

**仲裁案号兜底正则**（劳动/人事争议仲裁裁决书）：

```
[\u4e00-\u9fa5]{2,}仲案字[（(]\d{4}[）)]第\d+号
```

**规则**：
- 在文书全文中执行正则搜索
- **先**尝试上方法院案号正则；未命中时**再**尝试仲裁案号兜底正则
- 若命中多个案号，取**最先出现**的一个
- 输出案号**完整原文**（如 `(2024)粤0106民初1234号`），不做截断或改写
- 仲裁案号输出完整原文（如 `太劳人仲案字（2026）第952号`），保留括号与"第/号"原样
- 若未命中任何案号，输出 `null`

### 2. 原告/申请人（NER 实体识别）

**提取方式**：基于上下文触发词的实体识别

**触发词**（命中任一即启动识别）：`原告`、`申请人`、`起诉人`、`申诉人`、`再审申请人`、`上诉人`

**实体识别规则**：
1. 定位触发词在文书中的位置
2. 从触发词之后开始扫描，跳过标签分隔符（`：`、`:`、空格）
3. 提取紧随其后的实体名称，实体类型判定如下：
   - **自然人**：2–4 个连续汉字，支持少数民族姓名（含 `·` 分隔符，如 `买买提·艾力`），遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
   - **法人/组织**：以 `有限公司`、`股份有限公司`、`集团`、`公司`、`厂`、`社`、`院`、`中心`、`事务所`、`合作社`、`个体工商户` 等组织后缀结尾的连续文本，遇到 `，`、`,`、`；`、`。`、`、` 或换行符时终止
4. 一行内可能出现多个实体（以 `、`、`，` 分隔），全部提取
5. 跨行出现的多个原告（如"原告：张三\n原告：李四"），全部提取

**角色排除**：
- 排除审判人员（`审判长`、`审判员`、`法官`、`陪审员`）、书记员、代理人（`律师`、`法律工作者`）等角色人名，通过上下文角色词区分，仅提取当事人名称

**简称与全称**：
- 识别简称与全称的对应关系（如"番茄站公司"为"番茄站智能科技有限公司"的简称），同一实体保留**全称**

**冲突处理**：
- 若触发词后紧跟的是地址、电话等非名称信息（以 `住`、`住址`、`地址`、`电话`、`身份证` 开头），跳过该段，继续向后查找名称实体
- 若触发词后无任何可识别实体，该位置标记为未命中，继续搜索下一个触发词出现处

**输出**：数组，如 `["张明华"]` 或 `["张明华", "李四"]`；若无任何命中，输出 `null`

### 3. 被告/被申请人（NER 实体识别）

**提取方式**：同字段 2

**触发词**（命中任一即启动识别）：`被告`、`被申请人`、`被诉人`、`被申诉人`、`被上诉人`、`被传唤人`

**实体识别规则**：同字段 2 的规则 1–5

**角色排除**：同字段 2

**简称与全称**：同字段 2

**冲突处理**：同字段 2

**输出**：数组；若无任何命中，输出 `null`

### 4. 涉及主体（NER 实体识别）

**提取方式**：聚合所有具名当事人（**仅限备选主体名单内**）

**识别范围**：从以下角色上下文中提取全部实体名称，并对照第 0 节备选名单过滤：
- 原告/申请人（复用字段 2 结果）
- 被告/被申请人（复用字段 3 结果）
- 第三人：触发词 `第三人`
- 上诉人/被上诉人：触发词 `上诉人`、`被上诉人`
- 其他诉讼参与人：触发词 `证人`、`鉴定人`

**候选名单过滤**（硬性）：
- 仅保留与第 0 节备选名单**匹配**的实体（全称匹配或简称还原为名单全称）
- 名单外的自然人、法人一律剔除
- 简称还原：如 `番茄站公司` -> `番茄站智能科技有限公司`

**去重规则**：
- 同一实体名称（完全一致）仅保留一次

**输出**：数组，如 `["番茄站智能科技有限公司"]`；仅含名单内主体，若无任何命中，输出 `null`

**备注**：一期不接企查查，仅基于文书原文识别；四期增加工商库交叉验证。

### 5. 受理法院/仲裁委（NER 实体识别）

**提取方式**：模式匹配

**识别规则**：

按以下优先级依次尝试提取，取首个命中结果：

1. **从案号提取**（优先）：
   - 若字段 1 已提取到案号，从案号中提取法院/仲裁委代码部分（如 `(2024)粤0106民初1234号` 中的 `粤0106`），结合文书上下文还原为全称
2. **从文书全文正则匹配**：
   - 法院模式：`[\u4e00-\u9fa5]+人民法院`
   - 仲裁委模式：`[\u4e00-\u9fa5]+仲裁委员会`、`[\u4e00-\u9fa5]+劳动人事争议仲裁委员会`
3. **法院层级识别**：通过名称关键词判定层级：
   - `最高人民法院` -> 最高
   - `高级人民法院` -> 高级
   - `中级人民法院` -> 中级
   - 其余 `人民法院` -> 基层
4. 取**最先出现**的匹配结果

**输出**：单值字符串，输出**全称**，如 `"广州市天河区人民法院"`；若无任何命中，输出 `null`

#### 匹配规则

1. 对文书全文逐条执行关键词子串匹配，统计每个案由的命中关键词数量
2. **单案由命中**：仅一个案由命中关键词 -> 直接判定为该案由
3. **多案由命中**：取命中关键词数量最多者
4. **平局处理**：若多个案由命中数量相同，取映射表中**靠前**者（按上表顺序）
5. **特殊规则**：
   - "提供劳务者受害责任纠纷"与"提供劳务者致害责任纠纷"共享"提供劳务"关键词，须通过第二关键词（`受害`/`受伤`/`人身损害` vs `致害`/`致人损害`/`造成他人`）区分
   - 仅出现"提供劳务"而未出现任何第二关键词时，**两个案由均不命中**

#### 未命中处理

- 若所有案由关键词均未命中 -> `标准案由` 输出 `null`，注明 `未匹配到已知案由`
- **直接提取**：`标准案由` 名称**完整直接出现**在文书原文中（如文书写明"机动车交通事故责任纠纷"）-> 直接输出该案由，无需额外命中关键词
- **硬性约束（必须遵守）**：
  - 案由判定**只能**使用上方映射表中的关键词，禁止使用映射表之外的关键词（如"交通事故"、"借款合同"、"劳务纠纷"等）
  - 若映射关键词未命中、且案由名称未完整直接出现在原文中 -> `标准案由` **一律输出 `null`**，禁止根据文书内容自行推断、概括或输出任何案由

**输出**：单值字符串，如 `"机动车交通事故责任纠纷"`；若无命中，输出 `null`

### 8. 标的额（模式匹配 + 金额提取）

**提取方式**：关键词触发 + 金额正则匹配

**提取优先级**：**优先从原文提取**；原文未明确涉及标的额时，用"诉讼请求金额"（字段 10 提取结果）代替

**触发词**（命中任一即启动原文识别）：`标的额`、`标的金额`、`涉案金额`、`争议金额`

**识别规则**：
1. **优先从原文提取**：在文书中定位标的额触发词，在触发词后 **100 字符**范围内搜索金额正则匹配
2. **原文未涉及则用诉讼请求金额代替**：若原文未命中标的额触发词（或命中但未匹配到金额），取字段 10"诉讼请求金额"的提取结果（所有诉讼请求金额的总和）作为标的额
3. **金额标准化**：统一转换为以"元"为单位的**阿拉伯数字**数值
   - 汉字金额先归一化为数字：原文`二千元` -> `2000`、`两万元` -> `20000`、`一万零三百元` -> `10300`
   - `万元` 结尾 -> 数值 × 10000
   - `元` 结尾 -> 原数值
   - 去除千分位逗号（如 `50,000` -> `50000`）
   - **禁止四舍五入 / 截取小数位**：金额小数位按原文原样保留（如 `832552.665` 输出 `832552.665`，不得舍入为 `832552.67`、不得截断为 `832552`）；求和结果同样保留精确小数位，不得舍入
4. 原始金额文本记录在 `提取说明` 中

**输出**：数值（单位：元），如 `80000`；原文与诉讼请求金额均无任何命中，输出 `null`

### 9. 赔偿金（模式匹配 + 金额提取）

**提取方式**：同字段 8

**触发词**（命中任一即启动识别）：`赔偿金`、`赔偿款`、`损害赔偿`、`赔偿金额`

**识别规则**：同字段 8 的规则 1–4

**裁判主文兜底**：若上方触发词均未命中，但裁判结果主文（字段 11 定位到的主文）中出现法院判令"赔偿…<金额>元"（如 `赔偿原告邓小容79281.61元`），则提取该"赔偿"后第一个金额作为赔偿金；若主文中也无此内容，输出 `null`。

**输出**：数值（单位：元）；若无任何命中，输出 `null`

### 10. 诉讼请求金额（模式匹配 + 金额提取）

**提取方式**：关键词触发 + 金额正则匹配

**提取指标**：**单独提取所有"诉讼请求金额"后求和**（仅对每项诉讼请求对应的金额求和，不是对所有金额求和）

**触发词**（命中任一即启动识别）：`诉讼请求`、`请求判令`、`请求支付`、`请求赔偿`、`诉请`

**识别规则**：
1. 在文书中**逐项**定位诉讼请求相关触发词，对每项诉讼请求在其后 **100 字符**范围内搜索金额正则匹配
2. **逐项单独提取**：每项诉讼请求对应的金额独立识别、独立标准化（如 `请求支付劳动报酬50000元`、`请求支付赔偿金30000元` -> 分别为 `50000`、`30000`）
3. 将提取出的**所有诉讼请求金额**求和，输出**总和**
4. 若仅有一项诉讼请求金额，直接输出该金额
5. 金额标准化规则同字段 8

**撤回/变更不影响求和范围**：即使庭审中原告撤回部分诉讼请求，仍须按起诉状/申请书中列明的**全部**诉讼请求金额求和，不得因后续撤回、变更或部分支持而剔除任一项。

**输出**：数值（单位：元），为所有诉讼请求金额的**总和**；若无任何命中，输出 `null`

### 11. 裁判结果（主文提取）

**提取方式**：主文截取 + 关键词定位

**触发词**（命中任一即定位主文起点）：`判决如下`、`裁定如下`、`调解协议如下`、`协议如下`、`裁决如下`、`判决：`、`裁定：`、`决定如下`

**识别规则**：
1. 在文书全文中定位主文起点触发词
2. 从触发词**之后**开始截取裁判结果内容
3. **截取终点**（按优先级，命中任一即终止）：
   - 落款区域：`审判长`、`审判员`、`书记员`、`仲裁员`、`首席仲裁员`、`仲裁庭` 等签名词
   - 日期落款：文书末尾的 `XXXX年X月X日` 日期行
4. 裁判结果内容**原样保留**（包括分条编号如"一、""二、"，不做改写或删减）
5. 若文书中有多个主文段（如部分支持、驳回等多项），全部保留
6. **案件受理费按文书类型区别处理**：
   - **调解书/仲裁裁决书**：主文之后若紧接"案件受理费…由…承担/负担"句，一并保留；但不要继续保留"双方当事人一致同意本调解协议"、"上述协议，符合有关法律规定，本院予以确认"等程序性套话
   - **判决书/裁定书**：主文止于最后一项裁判项（如"驳回…其他诉讼请求"），**不包含**后续"案件受理费…负担"句

**提取方式示例**：
- `判决如下：\n一、被告于本判决生效之日起十日内向原告支付劳动报酬50000元；\n二、驳回原告其他诉讼请求。\n\n审判长...` -> 提取 `一、被告于本判决生效之日起十日内向原告支付劳动报酬50000元；二、驳回原告其他诉讼请求。`

**无法判定的情况**：
- 文书中无任何主文触发词 -> 输出 `null`，注明 `文书未包含裁判结果主文`
- 有触发词但触发词后至落款前无内容 -> 输出 `null`，注明 `裁判结果主文为空`

**输出**：字符串，**原样保留**裁判结果全文；若无，输出 `null`

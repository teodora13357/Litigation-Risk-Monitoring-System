# skills 法律文书解析技能

本目录存放法律文书解析的提示词技能（Prompt Skills），供大模型在文书识别流程中加载执行。整体遵循「先判型、再提取」的两段式设计：

1. **类型判定**：`file-type-classification` 先判定文书类型（仅判定，不提取字段）
2. **分类型提取**：根据判定结果，选择且仅选择对应的一个提取技能，按固定 JSON 结构输出字段

编排规则见 [AGENT.md](./AGENT.md)。

## 目录结构

```
skills/
├── AGENT.md                             # 总控提示词：类型判定 → 分发到对应提取技能
├── README.md                            # 本说明文件
├── file-type-classification/        # 文书类型判定（9 类可解析文书 vs 仅归档材料）
├── complaint-arbitration-extract/       # 起诉状 / 仲裁申请书字段提取
├── evidence-notice-extract/             # 举证通知书字段提取
├── judgment-ruling-mediation-extract/   # 判决书 / 裁定书 / 调解书字段提取
├── defense-notice-extract/              # 应诉通知书 / 参加诉讼通知书字段提取
├── summons-hearing-extract/             # 传票 / 开庭通知书字段提取
├── appeal-extract/                      # 上诉状字段提取
├── archived-field-extraction/           # 【已归档】旧版统一字段提取，不再参考使用
└── file-categorization/                 # 按人名/案件号整理当前文件夹文件（独立工具技能）
```

## 技能清单

| 技能 | 适用文书 | 提取字段数 | 说明 |
| ---- | ---- | ---- | ---- |
| `file-type-classification` | 全部 | - | 仅判定类型，区分「需完整解析的 9 类文书」与「仅归档存储的材料」 |
| `complaint-arbitration-extract` | 起诉状 / 仲裁申请书副本 | 9 | 原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、标的额、诉讼请求金额、赔偿金 |
| `evidence-notice-extract` | 举证通知书 | 7 | 案号、被告/被申请人、涉及主体、受理法院/仲裁委、标准案由、业务类型、举证期限 |
| `judgment-ruling-mediation-extract` | 判决书 / 裁定书 / 调解书 | 11 | 案号、原告/申请人、被告/被申请人、涉及主体、受理法院/仲裁委、业务类型、标准案由、标的额、赔偿金、诉讼请求金额、裁判结果 |
| `defense-notice-extract` | 应诉通知书 / 参加诉讼通知书 | 8 | 案号、原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、立案日期 |
| `summons-hearing-extract` | 传票 / 开庭通知书 / 改期开庭通知书 | 8 | 案号、被告/被申请人、涉及主体、受理法院/仲裁委、应到时间、标准案由、业务类型、应到地点 |
| `appeal-extract` | 上诉状 | 10 | 案号、原告/申请人、被告/被申请人、涉及主体、业务类型、标准案由、受理法院/仲裁委、标的额、诉讼请求金额、上诉请求 |
| `archived-field-extraction` | （旧版 9 类统一提取） | 15 | **仅存档，不再参考使用** |
| `file-categorization` | - | - | 独立工具技能：按案件号/人名归档当前文件夹文件，禁止删除、重命名、改内容 |

> 类型判定结果为「仅归档存储」或「未知类型」时，不执行任何字段提取，按对应技能规则终止。

### 涉及主体备选名单（硬性）

所有提取技能共用一个 **13 家备选主体名单**（番茄站智能科技有限公司、广东恒源数据服务有限公司、广东云天数字科技有限公司、广州考拉城技术有限公司、广州恒源信息技术有限公司、广州火烈鸟数字技术有限公司、广州跳跳虎数字技术有限公司、广州云鲸信息技术有限公司、广州昔之德信息科技有限公司、广东海诚实业发展有限公司、广东海润实业发展有限公司、广州汇兴信息技术有限公司、广东海德实业发展有限公司）。

- `涉及主体` 字段**只能**从名单中提取（全称或简称还原为名单全称），名单之外的实体一律不提取、输出 `null`
- 其他主体字段（原告/申请人、被告/被申请人）不受此约束，各 SKILL.md 第 0 节保持一致

### 标准案由（硬性）

- 案由判定只能使用映射表内关键词，**禁止使用映射表之外的关键词**（如"交通事故"、"借款合同"等）或根据文书内容自行推断
- 仅在「映射关键词命中」或「案由名称完整直接出现在文书原文」时输出，否则一律输出 `null`（各 SKILL.md「未命中处理」保持一致）

### 举证期限（evidence-notice-extract）

- 具体日期输出 `YYYY-MM-DD`（月、日补零）
- 相对期限**保留原文形式、逐字原样输出**：中文数字保留中文（`五天内`→`五天内`）、阿拉伯数字保留阿拉伯（`7日内`→`7日内`），禁止转换数字形式（否则溯源判定不通过触发重生成）

### 金额字段（标的额 / 赔偿金 / 诉讼请求金额）

- **一律输出阿拉伯数字**：金额统一为以"元"为单位的十进制数值（如 `2000`、`832552.665`），不得输出汉字/大写金额（不得输出 `二千`、`贰仟元`）
- 原文金额为汉字时先归一化为数字再输出（如 原文`二千元` -> `2000`、`两万元` -> `20000`、`一万零三百元` -> `10300`）
- 保留原文全部小数位，禁止四舍五入/截取（`832552.665` 不得输出 `832552.67`）
- 溯源侧会把原文汉字金额归一化为数字后与提取值精确比对（`2000` 可匹配原文 `二千元`/`贰仟元`）

## 通用硬性约束

所有提取技能共同遵循（详见各 SKILL.md 与 AGENT.md）：

1. 仅从文书原文提取真实存在的信息，禁止编造、推断或补全
2. 除指定字段外，不输出任何推理结果、分析意见或额外内容
3. 输出为固定 JSON 结构；文书不在可解析范围内时立即终止并输出 `{"错误": "该文书不在可解析范围内"}`
4. 禁止修改、移动、删除任何文件

## 文件规范

每个技能一个文件夹，包含：

- `SKILL.md`：技能正文，以 YAML frontmatter 开头（`name` + `description`），正文包含适用范围、硬性约束、字段定义、执行步骤与输出格式
- `.修改记录.md`：该技能的迭代修改日志（隐藏文件）

修改或新增技能时：

1. 保持 frontmatter 的 `name` 与文件夹名一致
2. 提取字段调整须同步更新 `description` 中的字段清单
3. 在对应 `.修改记录.md` 中追加变更记录
4. 涉及类型分发关系变更时，同步更新 `AGENT.md`

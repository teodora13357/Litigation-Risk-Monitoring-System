# 提取准确率排查总结

## 结论

当前 `testset/eval_report.json` 总匹配率：**91.60%（240/262）**，已达标（目标 ≥ 90%）。

## 本轮改动概览

1. **用 langgraph 重构提取 pipeline**
   - 将 `extractor_test/batch_test.py` 中原来的“判型 → 串行 voter 循环 → 投票收尾”改为 `StateGraph` 状态机：
     `classify → parse_check → extract（多 voter/重生成循环）→ collect → END`。
   - 增加 agent 按 `system_prompt` 缓存，减少重复构建 `create_agent`。
   - 提取响应非 JSON 时按空对象兜底，避免单篇文书整篇失败。

2. **归一化修复（scripts/provenance_utils.py）**
   - 标点归一化补齐 Unicode 连字符/破折号变体（`‐ ‑ ‒ – — ― −`），
     解决 GT 使用 `民事诉讼‑侵权纠纷`（U+2011）而结果使用 `民事诉讼-侵权纠纷`（U+002D）导致的误判。

3. **分类规则修复（prompts/skills/file-type-classification/SKILL.md + CLASSIFY_PROMPT）**
   - 9 类可解析文书新增“参加诉讼通知”关键词，修复“参加诉讼通知书”被误判为无需解析、整篇字段为空的问题。

4. **判决/裁定/调解 skill 修复（prompts/skills/judgment-ruling-mediation-extract/）**
   - 适用范围扩展为“判决书/裁定书/调解书/仲裁裁决书”，并新增仲裁案号兜底正则，修复 952 号仲裁裁决书整篇被拒解析。
   - 诉讼请求金额明确“撤回/变更不影响求和范围”。
   - 赔偿金新增“裁判主文兜底”。
   - 裁判结果“案件受理费”按文书类型区别处理（调解书/仲裁裁决书保留，判决书/裁定书不包含）。

5. **传票 skill 修复（prompts/skills/summons-hearing-extract/）**
   - 案由/业务类型映射新增“侵权责任纠纷”，修复“案由=侵权责任纠纷”时业务类型被判为无法推断。

## 建议下一步

- 优先处理 OCR 侧不稳定/明显错字：对接更稳定的 OCR 或对关键实体（法院/主体名）做候选白名单纠错。
- 复核 GT 中疑义项（银行卡号、案由、跨文档受理法院等），与业务方对齐后再决定是否改提取规则。
- 对“多项诉请求和”类金额，可在后处理中增加基于原文金额 token 的精确子集和还原（`restore_amount_precision` 已有基础），进一步提升金额字段稳定性。
